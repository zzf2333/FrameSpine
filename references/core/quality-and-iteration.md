## 原则

视频质量主要来自：

```text
清楚的观看承诺
+ 持续的局部回报
+ 图片真正承担内容
+ 时间和运动有层级
+ 用户看到真实播放后持续修正
```

不要把质量变成自动分数，也不要把技术检查当成创意验收。

用户是最终判断者，但 Agent 不是被动执行者。Agent 应先进行导演式自评，指出问题、给出原因和推荐修改，再让用户做选择。

## 审片不是一次总评

用户若被要求一次同时判断内容、图片、字幕、节奏、声音、转场和风格，反馈往往会变成：

> 好像哪里不对。

因此每次预览明确一个主要审片问题。可以完整播放多次，但每次关注不同层。

### 不要同时问十个问题

展示后先说：

> 这轮只重点判断两个问题：第一层回报是否太晚，以及第 3 段的图片是否真正证明了“选择成本”。视觉精修和音效暂时不看。

用户仍可以自由反馈其他问题，但主要判断会更清楚。

## 七轮审片法

这些不是七个强制审批阶段，而是七种观看视角。按当前成熟度选择使用。

## 第一轮：注意力审片

### 看什么

- 第一帧是否有具体事件；
- 第一段旁白是否直接进入；
- 第一层回报是否足够早；
- 中段哪里想划走；
- 是否不断获得新东西；
- 开头承诺是否最终兑现。

### 怎样看

不暂停，像真实抖音观看一样完整播放。

### Agent 记录

```text
最强 5 秒：
最弱 5 秒：
第一层回报时刻：
主问题关闭时刻：
最可能划走的位置：
```

这些是导演笔记，不是自动门禁。

## 第二轮：叙事与认知审片

### 看什么

逐段问：

- 进入时观众怎样理解；
- 本段新增了什么；
- 离开时理解如何变化；
- 证据是否足够；
- 段落之间是否因果相连；
- 是否有重复解释。

### 典型问题

> 第 2 段与第 3 段都在说计划带来负担，但没有新的层次。建议合并，或者让第 3 段负责一个真正不同的原因。

## 第三轮：图片叙事审片

### 看什么

- 图片是否证明内容；
- 哪些图只是气氛；
- 一张图是否承担了清楚的观看任务；
- 重大重构是否在画面中成立；
- 图片之间是否有视觉交接；
- 编辑文字是否替图片讲了太多。

### 怎样看

可以：

- 静音观看；
- 忽略编辑文字；
- 逐拍暂停；
- 只看缩略图序列。

### 核心问题

> 如果观众只读字幕而不认真看图片，是否会错过重要证据和关系？

若不会，图片可能太弱。

## 第四轮：时间与节奏审片

### 看什么

- 旁白是否过密；
- 复杂图片是否有阅读时间；
- 关键回报是否缺少停顿；
- 每个 Scene 是否同样快或同样慢；
- 转场是否抢内容；
- 字幕是否频繁闪过；
- 结尾是否被 CTA 挤压。

### 区分四种“慢”

1. **回报慢**：一直铺垫，解决内容结构；
2. **语言慢**：句子冗长，解决旁白；
3. **视觉慢**：图片没有新发现，解决图片节拍；
4. **动作慢**：动画时长过长，解决时间线。

不要一律全局加速。

## 第五轮：HyperFrames 视觉审片

### 看什么

- 英雄帧是否成立；
- 观众第一眼看什么；
- 元素出现顺序是否符合重要性；
- 图片运动是否有语义；
- 同一动画模式是否重复；
- 转场是否表达前后关系；
- 画面是否像网页或 PPT；
- 构图是否适合手机竖屏；
- 字幕是否与图片竞争。

### 观看方式

- 在关键英雄帧暂停；
- 慢速观看复杂段落；
- 在手机尺寸观看；
- 关闭声音检查视觉路径；
- 打开声音检查运动是否与语义同步。

## 第六轮：声音与字幕审片

### 看什么

- 火山 TTS 是否像该系列的说话者；
- Hook、解释、重构和回报是否有语气差异；
- 停顿是否自然；
- 音乐是否支持段落变化；
- 音效是否准确而克制；
- 中文和英文字幕是否自然；
- 字幕是否可读；
- 英文是否逐字硬译；
- 字幕是否遮挡关键主体。

字幕是基础功能，重点是无摩擦、可靠，不需要成为最抢眼的视觉层。

## 第七轮：完成度与平台审片

### 看什么

- 是否仍有占位图、临时声音或审核标注；
- 图片连续性；
- 生成图错误；
- 品牌资产；
- 来源与隐私；
- 抖音 UI 安全区；
- 片头、片尾和 CTA；
- 音量；
- 导出是否与预览一致；
- 手机真实观看效果。

技术上运行 lint、inspect、validate 和最终 render。

## Agent 展示预览的方式

不要只丢一个链接说“请验收”。

### 展示模板

```text
这版主要解决：
- 第一帧从抽象标题改成了具体异常。
- 第 18–25 秒增加了可见证据，不再只靠旁白解释。

我认为已经成立：
- Hook 与最终回报一致。
- 开头图片的回收现在更清楚。

我仍然不确定：
- 第 3 段的证据图阅读时间是否足够。
- TTS 在核心重构处是否需要更短停顿。

这一轮请重点看：
1. 你是否在 20 秒左右感到节奏变平？
2. “选择成本”这一层是否已经由图片看明白？

我的推荐：
- 若第 3 段仍然慢，优先删一行旁白，而不是再加速图片。
```

### 展示多个方案

说明差异和推荐：

```text
A：人物先行，情绪进入更快，但机制感较弱。
B：证据先行，可信度更强，但第一帧较冷。
C：违反直觉对比，最适合抖音，也最容易用图片证明。

我推荐 C 作为开头，同时借用 A 的人物回收。
```

不要把三个方案平铺给用户，却不表达专业判断。

## 用户反馈翻译表

用户的感受是有效证据，但通常不是直接实现指令。

| 用户反馈 | 可能的真实问题 | 先检查 | 不要直接做 |
| --- | --- | --- | --- |
| 不够抓人 | 第一帧弱、承诺泛、第一层回报晚 | Hook、图片异常、起句长度 | 全部动画加速 |
| 中间太平 | 没有新证据、局部回报或理解变化 | 注意力主干、段落、图片任务 | 随机加转场 |
| 太慢 | 回报、语言、视觉或动作之一慢 | 分别定位四种慢 | TTS 直接 1.5 倍速 |
| 太快 | 信息密度、字幕、图片阅读或转场过快 | 复杂画面、句长、停顿 | 全局减速 |
| 不高级 | 视觉过载、AI 图、字体、转场炫技、节奏无层级 | 具体画面和运动 | 黑金配色 |
| 像 PPT | 标题页结构、图片是背景、一次性出现 | 图片内揭示、空间层级、衔接 | 只换模板 |
| 图片不对 | 题材、证据、构图、情绪或连续性不对 | 图片任务和失败条件 | 同 Prompt 无限重抽 |
| 图片很漂亮但空 | 没有可见证据或关系 | 图片角色、图片证明 | 再加滤镜 |
| 文字太多 | 编辑文字重复旁白或图片弱 | 删除编辑文字、增强图片 | 缩小文字塞更多 |
| 字幕挡画面 | 构图未预留、安全区错误 | 图片裁切、运动终点、字幕位置 | 把字幕缩很小 |
| 动效太花 | 动作无语义、转场过多 | 主运动、转场系统 | 只降低透明度 |
| 动效太单调 | 所有图同一种运动、速度无对比 | 场景任务、速度和静止 | 每镜加新特效 |
| 声音没力量 | 文案起句、Voice、停顿或语速 | 先听单段 | 全片加音量 |
| 结尾没感觉 | 回报不完整、缺回收、CTA 抢结尾 | 最终回报和开头图 | 加更大 CTA |
| 画面不像这个系列 | Narrative Mode 不清、Reality Level 漂移，或创作自由没有服务真实锚点 | Narrative Contract、图片角色、旁白措辞与关键 Scene | 只换色调或加“更真实”的滤镜 |

## 修改正确层级

### 内容层

症状：价值弱、事实不足、主问题不值得看。

修改：选题、角度、证据、最终回报。

### 注意力层

症状：开头弱、中段平、答案拖延、反转不可信。

修改：Hook、回报顺序、证据位置、认知变化。

### 旁白层

症状：冗长、抽象、重复、难图片化、TTS 不自然。

修改：句子、顺序、案例、停顿、用词。

### 叙事契约层

症状：观众不清楚自己进入的是纪录、知识故事、电影叙事还是概念世界；综合人物、象征或幻想元素让主题变弱；旁白承诺与画面世界互相冲突。

修改：回到 `SERIES.md` 的 Narrative Mode、Reality Level、Story License 与 Truth Anchor；调整叙事措辞、图片角色和关键 Scene 的体验，而不是增加真实性评分或披露门。

### 图片任务层

症状：图片相关但不证明、视觉重复、重构不成立。

修改：图片角色、可见证据、构图、场景关系。

### HyperFrames 导演层

症状：焦点混乱、运动无意义、转场不连、像 PPT。

修改：英雄帧、观看顺序、GSAP、Scene 划分、转场。

### 资产层

症状：生成图错误、人物不一致、分辨率不足、声音不对。

修改：Prompt、参考图、选图、Voice、重新生成。

### 技术层

症状：溢出、路径错误、渲染失败、字幕不隐藏。

修改：HTML、CSS、时间线、媒体和 CLI 报告。

先找到层级，再动手。不要用下游精修掩盖上游问题。

## 怎样主动提出改进

Agent 应具备导演立场，但不把偏好伪装成客观真理。

### 好的建议包含

1. **观察**：具体发生了什么；
2. **原因**：为什么影响观看；
3. **建议**：优先修改什么；
4. **替代方案**：必要时给第二选择；
5. **权衡**：各方案会牺牲什么。

示例：

> 第 12–19 秒连续解释了“完成感”和“奖励”，但图片只停留在同一张计划表，认知已经推进，视觉没有推进。  
> 我建议让完成标记依次亮起，再切到仍为零的任务进度，这样图片能证明“奖励先于工作”。  
> 备选是删掉第二句解释，把这个机制留到后面。前者信息更完整，后者节奏更紧。

### 建议优先级

优先提出能明显改善：

- 最终回报；
- 第一层回报；
- 图片证明；
- 中段平坦；
- 结尾回收。

不要把大量精力放在用户尚未关注的细微装饰上。

### 保留不确定性

可以说：

> 我倾向 A，因为它让图片承担更多证据，但用户是否觉得第一帧过冷，需要实际观看判断。

这比假装存在唯一正确答案更可信。

## 怎样控制迭代范围

### 每轮设一个主要问题

例如：

- 本轮只修 Hook；
- 本轮只修第 3 段图片表达；
- 本轮只校准正式声音后的时间；
- 本轮只处理风格统一。

### 改动影响大时完整回看

修改以下内容后，应从头完整播放：

- Hook；
- 最终回报；
- 段落顺序；
- 正式 TTS；
- 关键图片；
- 核心转场；
- 结尾。

### 小修改局部回看

- 字幕换行；
- 单个裁切；
- 一处 easing；
- 小音量；
- 一处标注。

完成后仍做一次最终全片播放。

### 防止版本分叉

用户选定方案后，将获胜内容折回真实项目。不要长期维护 A/B/C 三套最终视频。

### 记录有效决定

在 `EPISODE.md` 或 `STORYBOARD.md` 简洁记录：

```text
保留 C 的第一帧，因为异常最具体。
使用 A 的人物回收，因为结尾更有情绪。
删除“选择成本”大字，图片已足够清楚。
```

不需要状态机或审批证据。

## 不同阶段的质量重点

### 系列初始化

质量来自：

- 系列价值清楚；
- 方向有辨识度；
- 校准片测试真实内容；
- 用户看过声音、图片和运动；
- `DESIGN.md` 可执行。

### Story Flow

质量来自：

- 注意力链完整；
- 局部回报持续；
- 段落承接；
- 开头与结尾匹配。

不要追求最终图片。

### Image Animatic

质量来自：

- 图片证明内容；
- 观看顺序清楚；
- 镜头关系成立；
- 字幕安全；
- 画面不重复。

### Timed Animatic

质量来自：

- 正式声音节奏；
- 字幕阅读；
- 图片停留；
- 快慢对比；
- 回报停顿。

### Final

质量来自：

- 最终资产；
- 连续性；
- 精细运动；
- 声音混合；
- 平台安全；
- 技术可靠；
- 用户完整观看后的认可。

## 系列一致性与单集新鲜度

系列一致性不等于每期套同一模板。

### 应保持稳定

- 系列价值和语气；
- 图片质感；
- 字幕层级；
- 字体和颜色角色；
- 主运动气质；
- 主转场家族；
- 编辑文字边界；
- 旁白角色。

### 应根据内容变化

- Hook 结构；
- 具体场景；
- 人物和物件；
- 图片节拍；
- 证据形式；
- 场景数量；
- 强调转场；
- 音乐能量；
- 结尾回收。

### 更新系列基线的时机

当多期反复出现同一改进，或 Provider、图片语言、长期人物、字幕系统发生明显变化时：

1. 提出系列级建议；
2. 做一个短校准片；
3. 用户观看；
4. 更新 `SERIES.md` 和 `DESIGN.md`。

不要让单期临时处理悄悄改变所有未来视频。

## 常见失败模式

### 1. 只问“满意吗”

用户难以给具体反馈。应说明本轮问题和 Agent 判断。

### 2. 用户反馈被逐字执行

“快一点”直接全局加速，而不分析原因。

### 3. Agent 过度防御方案

用户不喜欢时解释为什么设计正确，而不是学习。

### 4. Agent 没有立场

只给选项，不给推荐和权衡。

### 5. 一轮改太多

无法知道哪项改动真正有效。

### 6. 下游修上游

用滤镜、转场和动画修复价值弱、文案长或图片空。

### 7. 原型过度精修

方向未定就投入最终图片和音效。

### 8. 技术警告被当成创意评分

inspect 报告用于修布局，不决定视频是否吸引人。

### 9. 只在电脑看

不检查手机竖屏、字幕和抖音 UI。

### 10. 系列一致性变成复制

每期相同开头、构图和转场，内容失去新鲜度。

## 交付前最后观看

最终导出前完成四次完整观看：

### 1. 正常观看

不暂停，判断是否愿意看完。

### 2. 静音观看

检查图片、字幕和视觉结构。

### 3. 只听声音

检查旁白、音乐、音效和逻辑。

### 4. 手机观看

检查真实尺寸、抖音 UI、安全区、字幕和细节。

最后确认：

- 开头没有空白和栏目铺垫；
- 第一层回报明确；
- 核心证据可见；
- 最终回报完整；
- 图片不是装饰；
- 编辑文字克制；
- 双语字幕可靠；
- 没有占位或审核标注；
- 声音平衡；
- 渲染结果与 Studio 一致。
