# 叙事导演：把定稿文案完整导演成图片主导视频

这是一份 Episode Production 的导演方法，不是 Attention Spine 之外的第二核心。

当用户交付完整文案时，FrameSpine 的首要职责不是把它优化成另一篇短视频文案，
而是先读懂这段叙事怎样活着，再用图片、声音、节奏和 HyperFrames 让观众经历同一段叙事。

> 定稿文案默认是 Locked Script Mode 的源文本。除非用户明确要求 Revision Mode，不改写原句、不调整顺序、不为时长删句，也不把人物故事压缩成商业结论。

## 导演先读什么

### 讲述者

先回答：

- 谁在讲？
- 他为什么想讲这件事？
- 他对事件、人物和结论是什么态度？
- 他把观众当成正在被说服的人、一起发现的人，还是能理解他的人？

讲述者不是单纯的 TTS 音色。称呼、犹豫、惊讶、停顿和与观众说话的方式，都构成叙事立场。

### 事件链

不要只摘取结论。找出什么正在改变：

```text
起始处境
→ 触发事件
→ 尝试、等待或积累
→ 期待改变
→ 结果、落空或新的理解
→ 余韵或行动
```

人物行动、一个物件的状态、时间经过和前后处境，通常比抽象总结更适合被图片承接。

### 好奇与局部回报

从原文中提取已经存在的观看动力：

```text
问题
→ 部分答案
→ 更深的问题
→ 下一次回报
```

不要为了让逻辑更整齐而提前说完原文准备稍后才揭示的答案。图片可以让问题更可见、让局部答案更可读，但不替原文抢答。

### 三种观看变化

逐段记录观众发生的变化：

| 变化 | 要问的问题 |
| --- | --- |
| 认知 | 观众多理解了什么？ |
| 情绪 | 观众多感受了什么？ |
| 关系 | 观众与讲述者、人物或事件怎样靠近、疏离或共同判断？ |

同一句话可以同时承担几种变化。不要把情绪与关系降格成没有事实价值的填充。

## 句子不是只按信息价值分类

每句至少判断它主要承担什么功能：

| 功能 | 作用 |
| --- | --- |
| 信息 | 提供事实、原因、过程或结果。 |
| 情绪 | 让人物和观众感到惊讶、挫败、希望、落空或释放。 |
| 互动 | 给观众反应、判断、代入或共同发现的位置。 |
| 节奏 | 制造停顿、转折、期待、重复感或释放。 |

一句话没有增加新事实，不代表它冗余。

- “是不是听起来很离谱”让观众有一起判断的入口；
- “他也觉得离谱”把讲述者、人物和观众放进同一反应；
- “直到有一天”建立事件即将改变的期待；
- “三天，一个订单都没有”用节奏和具体时间承接落差。

在 Locked Script Mode 中，这些都是应保护的叙事资产。记录它们的功能，并让图片、停顿、声音或镜头停留承接它；不要因为它不解释机制就删除。

## 从原文到导演笔记

不复制或重写原文，只按原句顺序标注：

1. **段落边界**：叙事运动在何处改变；
2. **讲述者状态**：此刻的立场、语气和与观众的距离；
3. **事件变化**：什么具体对象、人物关系或处境变了；
4. **好奇与回报**：打开或关闭了什么问题；
5. **三种观看变化**：认知、情绪、关系；
6. **保护句**：互动、情绪或节奏功能为何不可替代；
7. **图片任务**：画面让观众看见、感受和期待什么。

由此得到的是 Extract Attention Spine 和图片节拍，不是一份替代旁白。

## 图片怎样承接原稿的生命力

每个节拍除“让观众理解什么”外，还要回答：

- 让观众感受到什么？
- 让观众接下来期待什么？
- 原文中哪一个互动、停顿、情绪或关系功能要由画面承接？

例如：

- 挫败可以由一个迟迟没有变化的物件、空白结果或等待中的人物承接；
- 希望出现时，让新的选择、光线、路径或动作真正进入画面；
- 期待落空时，不急于切图，用反应、空镜、结果或静止保留落差；
- 结尾回收同一个物件时，改变它与人物或结果的关系，使其获得新意义。

情绪图不能替代原文需要的证据、机制或事件；它们应与可见行动、对象和结果共同工作。

## 发现风险时怎么办

可以发现事实、逻辑、可理解性或时长风险，但 Locked Script Mode 的默认动作是**报告并导演**，不是擅自改稿：

- 时长过长：调整段落划分、图片密度、停留、声音分段、视频目标时长或建议拆集；
- 逻辑跳跃：通过图片中的事件、证据、回收或场景关系帮助观众跟上；
- 图片难表达：寻找原文中的人物、动作、物件、环境和前后状态，而不是删掉句子；
- 需要文字修改：明确说明原因、可修改范围和代价，等待用户进入 Revision Mode。

Revision Mode 中也只在用户允许的范围内修改，并保留讲述者、情绪、互动和节奏功能。

## 完成检查

在预览前问：

- 这仍像同一个人在讲吗？
- 人物还是人物，还是已被压成概念或案例摘要？
- 原稿的惊讶、挫败、希望、落空和释放是否还有位置？
- 互动句是否仍让观众可以反应？
- 图片是否让观众既能理解，也能感受和期待？
- 是否为了“更有效率”而让答案过早出现？

如果任一答案是否定的，先回到图片、声音、节奏和 Story Flow；只有用户明确要求，才回到文字修改。
