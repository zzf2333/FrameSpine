## 注意力主干是什么

注意力主干是观众持续观看的原因链，不是一个固定脚本模板，也不是“每三秒反转一次”。

它回答：

```text
观众为什么停下来？
此刻正在等待什么？
刚刚获得了什么？
理解发生了什么变化？
下一秒为什么仍然值得看？
开头承诺最终怎样兑现？
```

抖音观众不是在开头一次性决定看完，而是在不断重新评估“再看一秒是否值得”。因此视频需要持续提供真实进展：新信息、新证据、新对比、新理解、新后果或新用途。

注意力密度不等于剪辑密度。画面可以克制，但认知必须推进。

## 两种用法：Extract 与 Build

Attention Spine 仍是同一个观看动力链；不同的是 Agent 如何进入它。

### Extract Mode：定稿文案

用于 Locked Script Mode。读取原文，不改动顺序或措辞，提取：

```text
既有观看承诺
→ 局部问题与局部回报
→ 认知变化
→ 情绪变化
→ 讲述者与观众的关系变化
→ 可绑定的图片表达
```

Extract Mode 不是为原文发明替代 Hook 或替代回报。它让 Agent 看清已经存在的叙事，并把它完整导演出来。

### Build Mode：选题、文章和资料

用于 Development Mode。先确定最终回报，再构建观看承诺、局部回报、认知变化和图片链。用户明确要求改稿的 Revision Mode，也只在允许范围内使用 Build 方法。

## 四条必须对齐的链

### 1. 观看动力链

观众为什么继续：

```text
承诺
→ 进展
→ 局部回报
→ 新的值得追踪的问题
→ 核心兑现
```

### 2. 认知变化链

观众从什么理解走向什么理解：

```text
表面解释
→ 出现矛盾
→ 证据增加
→ 原解释不足
→ 新解释成立
→ 与自身发生关系
```

### 3. 图片表达链

每一步怎样在画面中看见：

```text
异常结果图
→ 具体行为图
→ 证据细节
→ 前后对比
→ 机制关系
→ 结尾回收图
```

### 4. 回报兑现链

视频有没有偿还它打开的问题：

```text
主问题：最终关闭
局部问题：短时间内关闭或给进展
视觉线索：后续回收
开头承诺：最终回报不低于承诺
```

四条链不对齐时会出现：

- 旁白一直推进，图片只是相关配图；
- 图片不断切换，但认知没有变化；
- 开头承诺 A，中间讲成 B；
- 一直打开问题，却没有局部回报；
- 反转只靠一句“其实”，没有证据。

## 先设计最终回报

写 Hook 之前，先写一句最终回报：

> 观众看完后，比看之前具体多获得了什么？

区分四个概念：

### 主题

视频谈论什么。

> 拖延。

### 内容结论

作者认为原因是什么。

> 复杂计划会增加选择成本。

### 最终回报

观众最终得到的完整价值。

> 观众理解自己不一定缺自律，而可能把行动变成了过多决策；并知道有效计划的作用是减少当下的选择。

### 观看承诺

开头可以诚实承诺什么。

> 为什么越认真做计划，反而越容易拖延？

最终回报需要满足：

- 具体，而不是“了解更多”；
- 对目标观众有意义；
- 能在短时长内被证明；
- 能由图片呈现或支持；
- 不弱于开头承诺。

若回报太弱，先改善选题或角度，不要用更夸张的 Hook 包装。

## 观看承诺与钩子

有效 Hook 通常同时包含：

```text
具体事件或异常
+ 与观众有关的利益、代价、身份或困惑
+ 一项可以兑现的观看承诺
```

Hook 不是单句文案。它至少由以下共同构成：

- 第一帧图片；
- 第一段旁白；
- 图片的第一层变化；
- 双语字幕；
- 第一个尚未解决的问题；
- 第一层回报的预告。

### 第一帧要求

第一帧应让观众立即看到一个具体对象、结果、冲突、证据或未完成事件。不要先出现：

- 栏目 Logo；
- 问候；
- “今天我们来聊”；
- 与主题无关的氛围图；
- 大段标题；
- 还没有信息的抽象背景。

### 第一层回报

不要让观众一直空等。Hook 后应尽快给第一条真正有价值的信息：

- 一个原因；
- 一条证据；
- 一个前后差异；
- 一个局部答案；
- 一个推翻表面解释的细节。

第一层回报不是完整答案，但必须让观众感觉已经得到东西。

## 钩子类型库

选择钩子时，先看内容本身最强的证据与视觉，不要为了套类型而扭曲事实。

### 1. 违反直觉

**结构**：熟悉行为 → 意外结果。

**适合**：机制解释、认知偏差、行为与结果不一致。

**图片形态**：

- 同一行为导致相反结果；
- 完成的计划表与未开始的任务并置；
- “省钱”按钮与未来账单并置。

**风险**：为了反直觉而夸大。必须在视频中尽快证明。

### 2. 结果先行

**结构**：先看后果 → 回溯原因。

**适合**：人物故事、商业后果、流程失败、变化过程。

**图片形态**：

- 空账户、关闭的店、堆积的退货；
- 开头先给终局，再回到第一步。

**风险**：结果很大，但原因与观众无关。要明确观看价值。

### 3. 具体异常

**结构**：熟悉场景里出现一个不合理细节。

**适合**：日常机制、消费、职场、产品体验。

**图片形态**：

- 任务没动，计划工具却越来越复杂；
- 商品变便宜，购物车总价却变高。

**风险**：异常不够具体，只剩“你有没有发现”。

### 4. 证据先行

**结构**：先展示一个可信但令人疑惑的证据。

**适合**：调查、商业、数据、历史、产品机制。

**图片形态**：

- 账单、文件、聊天、界面、统计、合同细节；
- 放大一个关键数字或条款。

**风险**：证据本身难读，第一帧信息过载。只聚焦一个疑点。

### 5. 人物困境

**结构**：一个具体人物面临选择、压力或代价。

**适合**：人物故事、职业、家庭、创业、消费。

**图片形态**：

- 行动前的关键时刻；
- 同一人物被两种选择拉扯；
- 结果已经发生，但人物还不知道原因。

**风险**：人物只是情绪插图，没有可追踪的行动。

### 6. 代价或利益

**结构**：观众熟悉的行为正在产生未被察觉的成本或机会。

**适合**：商业、效率、消费、健康习惯等。

**图片形态**：

- 小额选择逐步累积成大结果；
- 同样时间、金钱或注意力的不同去向。

**风险**：灾难化表达。代价必须可证明。

### 7. 未完成事件

**结构**：画面停在结果即将发生的瞬间。

**适合**：人物、实验、操作过程、因果演示。

**图片形态**：

- 手指即将点击；
- 商品即将进入结算；
- 一张关键文件尚未完全展开。

**风险**：只制造悬念，没有内容价值。

### 8. 前后差异

**结构**：同一主体、相似构图、关键变量变化。

**适合**：环境影响、产品效果、行为结果、时间变化。

**图片形态**：

- 人物不变、环境变化；
- 相同预算、不同购物结果；
- 相同产品、不同定价框架。

**风险**：只做视觉变身，没有解释变量。

### 9. 隐藏原因揭示

**结构**：先让观众看到表面 → 拉远或分层看到真正原因。

**适合**：系统机制、环境因素、商业结构。

**图片形态**：

- 先聚焦人物，随后拉远看到周围干扰；
- 先看一次购买，再展开会员、积分和沉没成本。

**风险**：所谓隐藏原因只是另一句观点，没有视觉证据。

## 局部回报阶梯

一条短视频不能只有一个大悬念和最后答案。更稳定的结构是：

```text
主承诺
→ 第一层答案
→ 新证据说明答案不完整
→ 更深解释
→ 与观众自身连接
→ 核心兑现
```

### 局部回报的形式

- 回答一个小问题；
- 给出一个可验证事实；
- 解释一个局部因果；
- 让一张图片中的异常得到解释；
- 展示一个前后结果；
- 给出一个可立即理解的术语；
- 让观众重新理解刚才的场景。

### 回报与再承诺

一个局部循环可写成：

```text
承诺：这不是你以为的原因
进展：先看一个具体行为
回报：这个行为提前制造了完成感
再承诺：但真正让行动更难的还有第二层
```

每次再承诺必须建立在刚刚给出的回报上，不能凭空开启无关悬念。

### 问题数量

短视频同时保持：

- 一个贯穿全片的主问题；
- 一个正在处理的局部问题；
- 偶尔一个视觉伏笔。

同时打开过多问题会造成混乱，而不是增加好奇。

## 注意力事件库

这些是功能，不是固定顺序。

### Hook

提出值得继续看的承诺。

### Anomaly 异常

建立“不应该这样”的具体矛盾。

### Question 问题

让观众知道当前要弄清什么。

### Reveal 揭示

出现之前不可见的信息。

### Evidence 证据

让判断从观点变成可信事实。

### Contrast 对比

在同一观看单位中看见差异。

### Escalation 升级

风险、代价、范围或意义变得更大。

### Reframe 重构

改变解释对象或角度，例如从“人不自律”转向“环境增加选择成本”。

### Payoff 局部或最终回报

关闭一个已经打开的问题。

### Application 应用

把机制带回观众自身或一个具体行动。

### Callback 回收

重用开头图片、物件、构图或句子，赋予新意义。

### CTA

在价值兑现后，要求关注、评论、尝试或观看下一期。

CTA 不是最终回报的替代品。

## 怎样避免平坦区

平坦区不是“没有动画”，而是观众的认知、情绪、关系或期待没有变化。

### 常见症状

- 连续多句背景解释；
- 同一结论换词重复；
- 图片只慢推近，没有新信息；
- 每张图都相关，却没有因果关系；
- 一直列原因，没有阶段性总结；
- 悬念拖延太久；
- 反转后没有证据；
- 结尾重复旁白，没有视觉兑现。

### 修复方法

先判断每句承担信息、情绪、互动还是节奏功能。没有新增事实的互动句、停顿句和人物反应，仍可能是观看动力的一部分。

Locked Script Mode 优先：

1. 让图片继续揭示，而不是无意义切图；
2. 为证据、反应、期待与回报安排停留；
3. 用场景关系、声音和可见事件承接原句；
4. 调整图片密度和段落节奏，不改写源文本。

Development / Revision Mode 才可以：

1. 删除没有改变理解、情绪、关系或期待的句子；
2. 把抽象解释换成具体行为或证据；
3. 提前局部回报或结果图；
4. 合并相似原因；
5. 用前后对比替代长解释。

### 注意力推进检查

对每个 3–8 秒区间问：

```text
观众刚刚学到、看到、感受到或与讲述者共同判断了什么？
如果拿掉这段，信息、情绪、互动、节奏或核心体验会损失什么？
```

Locked Script Mode 若答案不明确，先调整图片揭示、停留、声音或场景关系；Development / Revision Mode 才考虑删改。

## 怎样让图片承担注意力

每个关键注意力事件都需要视觉形态。

### 异常

用具体矛盾建立，不依赖大字宣布。

### 证据

让观众看见关键细节；必要文字在 HyperFrames 中准确叠加。

### 重构

保持一个变量不变，让解释对象变化：

- 人物不变，环境变化；
- 商品不变，定价框架变化；
- 行为不变，反馈时机变化。

### 升级

通过数量、范围、时间或后果累积呈现，不只靠旁白说“更严重”。

### 回报

让最终机制、结果或行动在画面中完成：路径收束、环境简化、前后对比闭合、证据链完整。

### 回收

返回开头构图，但改变其中一个关键关系，使观众用新理解重新看它。

## 按时长调整密度

下面是设计倾向，不是秒数硬规则。

### 15–25 秒

适合单一异常、一个解释和一个回报。

```text
Hook
→ 快速证据 / 对比
→ 核心解释
→ 回收或行动
```

不要塞入多个平行原因。

### 25–45 秒

可以包含两层解释与一次明显重构。

```text
Hook
→ 第一层回报
→ 新证据
→ 重构
→ 核心回报
→ 回收
```

这是图片主导知识短视频的常用区间。

### 45–60 秒

需要更强局部回报和节奏对比。可以有：

- 两到三个主要段落；
- 多个证据；
- 一次意义升级；
- 更完整的应用。

不要把额外时长变成长背景介绍。

### 60 秒以上

若内容仍适合抖音，需要：

- 明确章节变化；
- 更强的段落级回报；
- 图片语言变化但系列身份稳定；
- 必要时拆成两期，而不是强行压满。

## Build Mode：从原始内容构建主干

### 第一步：提取内容价值

从资料中找：

- 最违反直觉的事实；
- 最具体的证据；
- 目标观众最容易误解的地方；
- 最大后果；
- 最能图片化的场景；
- 最终真正有用的理解。

### 第二步：写最终回报

一句话，不写文案腔。

### 第三步：列出 2–3 个 Hook 方向

要求结构不同：

- 结果先行；
- 异常场景；
- 证据先行。

### 第四步：设计第一层回报

Hook 后最早能给什么真东西？

### 第五步：设计认知变化

观众最初的解释是什么？什么证据让它不足？新解释如何成立？

### 第六步：绑定图片

每个关键事件写出可见证明，不写“相关配图”。

### 第七步：写旁白

旁白负责连接、解释和节奏，不重复图片已经清楚表达的每个细节。

## Hook Lab

这是 Build Mode 或用户允许修改开头的 Revision Mode 工具。Locked Script Mode 默认不做 Hook Lab；可以测试第一帧和图片关系，但不改动原文开头。

当开头方向不确定时，用 HyperFrames 做 Hook Lab。

### 数量

默认 3 个，最多 5 个。超过 5 个通常会变成噪音。

### 差异要求

候选应在以下至少两项上真正不同：

- 第一帧；
- 观看承诺；
- 图片结构；
- 信息揭示顺序；
- 旁白角色；
- 第一层回报。

只换颜色、字体或同义句不算不同方案。

### 公平比较

使用相同：

- 最终回报；
- 代表性内容；
- 大致时长；
- 系列视觉基线。

### 用户反馈

鼓励混合：

> A 的第一帧更强，B 的旁白更可信，C 的拉远揭示更好。

Agent 应把获胜部分折回真实 composition，而不是保留所有候选进入最终工程。

## 审片与修改

### 第一轮：观看动力

不暂停看完整条：

- 哪一秒最想划走；
- 第一层回报是否太晚；
- 中段是否只剩解释；
- 结尾是否值回开头。

### 第二轮：叙事变化

逐段问：

- 看前如何理解、感受，以及与讲述者的距离；
- 看后哪些认知、情绪或关系发生变化；
- 证据和事件是否足以支持改变；
- Locked Script Mode 是否仍保持原文的讲述者、互动与节奏。

### 第三轮：图片证明

静音或忽略编辑文字观看：

- 图片是否承担了异常、证据、重构和回报；
- 哪些镜头只是氛围。

### 修改优先级

1. 回报、事件和结构；
2. 图片任务、图片运动与转场；
3. 声音、停留和节奏；
4. 视觉精修；
5. 仅在 Development / Revision Mode 或用户明确许可时，修改旁白长度与顺序。

不要用动画修复一个没有回报的段落。

## 常见失败模式

### 只有开头 Hook

前三秒很强，中间变成文章朗读。需要完整回报阶梯。

### 每段都强行反转

频繁“其实”“但你错了”会失去可信度。使用证据、对比和局部答案创造变化。

### 无限延迟答案

不给局部回报，只在最后宣布普通结论。观众没有理由相信等待会有价值。

### 钩子与回报不匹配

开头承诺“根本原因”，结尾只给一个技巧。

### 视觉钩子靠大字

图片没有异常，大字写“你一直都错了”。这不是图片主导。

### 复杂等于密集

每秒换图、元素全动、画面过载。应保持单拍一个主要观看任务。

### 证据出场太晚

观点讲了很久才给证明。把证据提前用于第一层回报。

### CTA 挤掉回报

最后几秒只剩关注提示。先完整兑现，再简短 CTA。

## 微型案例

主题：为什么免费试用常常让人花得更多？

### 最终回报

观众理解免费试用真正改变的是比较基准和退出成本，而不只是“诱导消费”。

### Hook A：结果先行

- 图片：0 元试用按钮与三个月连续扣款账单同屏；
- 旁白：真正贵的，往往不是你付钱买下的东西；
- 第一层回报：免费不是终点，而是把退出变成一个需要主动做的决定。

### Hook B：未完成事件

- 图片：手指即将点击“开始免费试用”，背后日历页面快速展开；
- 旁白：这个 0 元按钮，正在替三十天后的你做决定；
- 第一层回报：默认续费把未来的不行动变成付费。

### 注意力主干

```text
0 元按钮建立异常
→ 日历和默认续费给第一层答案
→ 用户已经投入设置与使用，退出成本上升
→ 相同产品在“已拥有”框架下被重新评价
→ 免费改变的不是价格，而是比较基准
→ 回到开头，按钮旁出现“取消需要主动行动”的真实关系
```

### 图片链

```text
按钮
→ 日历
→ 设置流程与使用记录累积
→ 取消页面的摩擦
→ 已拥有 / 未拥有前后对比
→ 开头按钮回收
```

这里不需要每三秒大反转，但每段都有新的可见信息和理解变化。
