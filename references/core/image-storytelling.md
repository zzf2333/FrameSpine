## 图片主导的真正含义

图片主导不是“画面里一直有图片”，也不是“每句话配一张相关图”。

它意味着：

> 视频中的核心事实、处境、变化、证据、关系和结果，主要通过图片本身、图片之间的关系，以及图片在时间中的变化被看见。

中文字幕和英文字幕是基础语言同步层。字幕之外的编辑文字不能替代图片叙事。

### 判断一张图片是否有效

问四个问题：

1. 它增加了旁白之外的什么可见信息？
2. 它证明了什么，而不只是“和主题相关”？
3. 它在这一刻为什么比上一张图更有价值？
4. 它怎样帮助下一拍发生？

若答案只是：

> 让画面不空、营造氛围、和话题相关。

它更像装饰资产，不是主要叙事图片。

### 95% 图片表达如何使用

不要计算机械分数。把它当作导演标准：

- 每个核心信息点都有可见表达；
- 重大重构和最终回报有图片证明；
- 去掉编辑文字后，核心结构仍成立；
- 图片不是重复字幕；
- 图片运动释放新信息，而不只是让静态图“动起来”。

## 从内容到图片任务

不要从 Prompt 开始。先定义图片任务。

### 内容句

> 复杂计划会增加选择成本。

### 无效图片任务

> 一个人在办公室纠结。

它只表达泛泛情绪，无法证明机制。

### 有效图片任务

> 保持同一人物和同一任务不变，随着计划表增加颜色、标签、时间块和优先级，人物面前的可选路径逐步增多；真正的“开始按钮”反而越来越远。最后所有路径收束为一个立即可做的动作。

这个任务已经包含：

- 不变变量；
- 变化变量；
- 可见因果；
- 动态揭示；
- 最终回报；
- 可供 HyperFrames 编排的层次。

### 图片任务模板

```text
这一拍要让观众看见：

保持不变的是：
发生变化的是：
变化造成的结果是：
关键证据位于：
第一眼看：
随后发现：
最终理解：
进入下一拍的视觉线索：
```

不必每次写满，但 Agent 要能回答。

## 图片角色库

一条视频通常混合多种图片角色。系列可以有偏好，但不要每期只用一种。

### 1. 场景建立图

让观众快速知道人物在哪里、正在做什么、处境是什么。

适合：人物故事、日常异常、空间关系。

设计重点：

- 具体行为，不是摆拍；
- 可继续揭示的环境细节；
- 主体与字幕安全区；
- 进入下一层信息的视觉路径。

### 2. 人物处境图

承载选择、压力、代价和情绪。

有效人物图通常有：

- 明确动作；
- 具体对象；
- 决策或后果；
- 与环境发生关系。

“人物扶额看电脑”通常信息不足。

### 3. 行为过程图

呈现一步步发生的动作：

- 注册；
- 购买；
- 规划；
- 选择；
- 取消；
- 反复修改；
- 累积投入。

适合用一张图的分层变化，或一组构图连续的图片。

### 4. 对比图

通过控制变量让差异成立：

- 人物不变，环境变化；
- 商品不变，定价方式变化；
- 预算不变，购买结果变化；
- 行为不变，反馈时机变化。

尽量保持构图相似，减少无关差异。

### 5. 证据图

文件、账单、界面、合同、新闻、数据、商品、收据、聊天记录。

证据图的任务不是展示整页，而是让一个关键事实可被看见。

常用做法：

```text
先建立证据来源
→ 局部放大
→ 高亮关键细节
→ 让细节与前一幕或后一幕建立关系
```

### 6. 机制图

表现看不见的因果、反馈、选择路径和系统关系。

它可以由：

- 场景中的物件抽象成图形；
- 多张图片 + SVG 线条；
- 标签与方向；
- 前后状态；
- 层级展开。

机制图不必像信息图表。仍然可以保持图片质感和叙事空间。

### 7. 后果图

呈现成本、变化和结果。

优先具体后果：

- 账户余额；
- 时间被占用；
- 购物篮变化；
- 任务进度；
- 人物关系；
- 空间状态；
- 重复行为累积。

### 8. 情绪承载图

用于让观众感受压力、孤立、欲望、松弛或释然。

情绪图不宜长时间单独承担机制解释。它通常服务人物段落、停顿或回报后的余韵。

### 9. 过渡图

改变空间、时间或情绪，为下一段准备。

它仍应带有视觉线索，不要只是无关空镜。

### 10. 回收图

重新使用开头主体、构图、物件或动作，但改变其中的关系。

回收让结构产生完成感，也是图片主导视频最有力的结尾方式之一。

## 抽象内容如何图片化

抽象内容通常不能靠“一个概念对应一个象征图标”解决。

### 方法一：找具体行为

抽象：

> 沉没成本让人难以退出。

具体：

- 用户已经设置账户、上传资料、建立收藏；
- 退出意味着重新开始；
- 取消按钮被放在更深路径；
- 之前投入的步骤以可见物件累积。

### 方法二：控制变量

抽象：

> 环境影响行为。

可见：

- 同一人物、同一任务、不同环境；
- 干扰源依次出现，结果改变；
- 环境简化后行动开始。

### 方法三：让数量累积

抽象：

> 小成本最终变得很大。

可见：

- 每次小额付费形成一层；
- 日历、账单或购物物件逐步堆积；
- 最终总体结果出现。

### 方法四：把因果拆成状态变化

抽象：

> 提前奖励削弱行动。

可见：

```text
完成计划表
→ 大脑得到完成反馈
→ 真正任务仍是零进度
→ 下一步行动吸引力下降
```

### 方法五：用前后解释同一画面

开头看到一个人没有行动，观众以为是懒惰；结尾回到同一画面，环境和选择路径被揭示，观众重新解释它。

### 方法六：用具体物件承载机制

- 会员卡承载锁定；
- 计划表承载选择；
- 账单承载延迟成本；
- 通知承载环境干扰；
- 购物篮承载比较基准；
- 门槛、路径和入口承载摩擦。

### 方法七：用空间关系表达抽象关系

- 更远：行动成本提高；
- 更多岔路：选择成本；
- 包围：环境压力；
- 收束：决策简化；
- 遮挡：信息隐藏；
- 放大：证据变得重要；
- 替换：认知重构。

## 图片节拍的结构

图片节拍是一个可见信息变化单位，不等同于场景或图片文件。

### 一个完整节拍包含

#### 1. 叙事任务

这拍在故事中完成什么？

#### 2. 注意力任务

它提供异常、证据、对比、揭示、升级、重构还是回报？

#### 3. 图片证明

具体哪个可见关系让内容成立？

#### 4. 第一眼焦点

观众最先看什么？

#### 5. 第二层发现

随后通过运动、遮罩、裁切或新增元素发现什么？

#### 6. 英雄帧

信息最完整、布局最清楚的瞬间是什么？

#### 7. 动态过程

进入、发展、强调、交接。

#### 8. 与旁白关系

- 图片先于旁白；
- 旁白先提问题，图片回答；
- 同步揭示；
- 图片提供旁白未说的证据；
- 图片与旁白形成对比。

#### 9. 字幕安全区

双语字幕在所有运动状态下是否安全？

#### 10. 失败条件

怎样的图片会让这一拍失效？

例如：

> 如果只画一个纠结的人，这一拍就无法证明选择成本。

### 图片节拍模板

```markdown
## Beat 04 — 计划变成选择题

- 叙事作用：从“提前完成感”推进到第二层原因。
- 注意力作用：Reframe。
- 对应旁白：于是你不是缺执行力，而是把行动变成了另一场选择题。
- 图片证明：人物不变，面前可选路径逐步增加，任务入口被推远。
- 第一眼：人物与唯一任务。
- 随后发现：颜色、标签和时间块变成多条岔路。
- 英雄帧：人物面对完整岔路网络，任务仍未开始。
- 进入：延续上一拍计划表中的一条线。
- 发展：岔路逐条增长。
- 强调：所有岔路同时停住，任务入口在远处。
- 交接：其中一条线收束为下一拍的单一动作。
- 编辑文字：可选“选择成本”，短暂命名，不解释。
- 字幕安全区：下方 30%，路径不进入该区域。
- 失败条件：人物只表现纠结，缺少路径增加的可见机制。
```

## 一张图承担多个节拍

图片主导视频不需要频繁换图。一个精心设计的场景可以连续释放多层内容。

### 例：办公桌场景

#### Beat 1：建立人物

聚焦人物准备工作。

#### Beat 2：拉远揭示环境

手机通知、聊天窗口、桌面杂物出现。

#### Beat 3：局部聚焦

通知数量和任务切换被高亮。

#### Beat 4：机制化

通知之间用图形路径连接，形成环境干扰网络。

#### Beat 5：交接

一条通知线延伸到下一个平台机制场景。

优势：

- 空间连续；
- 观众理解成本低；
- 图片价值被充分利用；
- 运动本身承担叙事；
- 减少随机配图感。

### 适合共享同一场景的情况

- 观众是在同一空间中逐步发现信息；
- 同一主体发生状态变化；
- 机制从具体场景中生长出来；
- 一个证据被逐层放大；
- 同一构图用于前后比较。

### 应该换场景的情况

- 叙事空间或时间真正改变；
- 当前场景已经无法承载新信息；
- 需要用强对比重置注意；
- 进入新的证据类型；
- 发生主要认知重构；
- 场景复杂度已经过高。

## 图片序列与镜头衔接

镜头衔接首先是语义关系，其次才是转场效果。

### 1. 主体接力

前一镜中的物体成为下一镜主角。

例：计划表中的红色标签放大，变成下一镜的“奖励反馈”指示灯。

### 2. 动作接力

一个动作在下一镜继续。

例：手指点击 → 下一镜按钮状态变化。

### 3. 方向接力

前一镜向右移动的视线或物体，在下一镜继续向右。

### 4. 轮廓匹配

相似形状连接不同场景。

例：圆形完成标记 → 奖励反馈灯。

### 5. 色彩接力

一个关键色块覆盖画面，成为下一场景的主色。

### 6. 局部放大

从当前图中的细节持续放大，进入新的图片或机制层。

### 7. 因果接力

前一镜的动作结果直接成为下一镜画面。

### 8. 同构替换

保持构图，只替换环境、人物状态或关键变量。

### 9. 问题与答案

前一镜提出可见问题，下一镜以证据回答。

### 10. 回收

与开头相似构图重新出现，完成闭环。

不应先选 wipe、glitch 或 crossfade，再勉强解释关系。先明确前后语义，再选择 HyperFrames 转场。

## 构图、字幕与运动余量

双语字幕是固定存在的基础层，构图必须从生成图片之前就考虑。

### 字幕安全区

不要只在最终合成时加字幕。图片任务中说明：

- 字幕默认区域；
- 中文与英文合计高度；
- 关键主体保护区；
- 推近后主体是否进入字幕区域；
- 平移终点是否被遮挡；
- 证据文字是否与字幕竞争。

### 主体位置

根据后续运动设计：

- 需要向右平移：左侧有起点，右侧有可探索信息；
- 需要拉远：图片原始分辨率和四周内容足够；
- 需要推近：关键细节清晰，裁切后仍成立；
- 需要编辑文字：预留不影响主体与字幕的空间；
- 需要分层：前景、主体、背景边界清楚。

### 运动余量

Prompt 可明确：

- wider composition for slow horizontal pan；
- extra negative space in upper-left；
- subject protected above lower subtitle zone；
- high-resolution details for 130% push-in；
- readable evidence area positioned mid-frame；
- no critical object near crop edges。

### 平台 UI

抖音按钮、标题和字幕区域会占用边缘空间。关键主体、编辑文字和证据不要贴近右侧和底部危险区。

## 图片运动的导演语言

动作不是效果菜单，而是信息编排。

### 进入 Entry

观众第一次怎样看到这张图：

- 从细节开始；
- 从整体开始；
- 图片从上一镜的物体延续；
- 遮罩打开；
- 主体先出现，环境后出现；
- 证据先出现，来源后建立。

### 发展 Development

图片在展示期间如何增加信息：

- 推近关键细节；
- 拉远揭示环境；
- 横移发现第二主体；
- 多图逐步累积；
- 局部亮度或遮罩改变；
- 图形关系逐步连接；
- 前后状态替换。

### 强调 Emphasis

关键语义落点：

- 短暂停顿；
- 局部对比变化；
- 轻微 scale；
- 证据框或标记；
- 其他层弱化；
- 编辑文字短暂命名。

强调不等于所有元素弹一下。

### 交接 Handoff

把下一镜需要的元素带出去：

- 方向；
- 物体；
- 形状；
- 色块；
- 线条；
- 动作；
- 视线；
- 因果结果。

### 静止的价值

重要回报、情绪和证据需要阅读时间。所有画面都在运动会削弱层级。让最重要的时刻短暂静止，常比再加一个动作更有力量。

## 编辑文字与图形

### 编辑文字允许的作用

- 给已经由图片成立的概念命名；
- 锁定关键数字；
- 标注人物、地点、来源或时间；
- 突出真正的认知转折；
- CTA。

### 编辑文字不应承担

- 完整复述旁白；
- 解释图片没有表达清楚的核心机制；
- 每个镜头的标题；
- 长定义；
- 为了“有设计感”而常驻。

### 图形层

箭头、路径、框线、蒙版和标签可以帮助图片表达关系，但要服务证据与观看顺序。

- 线条应连接真实对象；
- 标签数量保持少；
- 颜色角色一致；
- 不要把每张图片都变成信息图；
- 精确文字和数字优先用 HyperFrames 叠加。

## GPT Image 2 生产方法

### Prompt 从图片任务编译

一个成熟 Prompt 至少包含：

```text
1. 这张图片在故事中的任务
2. 必须可见的主体、动作和证据
3. 环境和时间
4. 构图与主体位置
5. 字幕安全区
6. 图片运动和裁切余量
7. 与前后镜头的视觉连续性
8. 系列图片质感、色彩和镜头语言
9. 必须避免的错误
```

### Prompt 示例

弱：

> 一个年轻人在办公室做计划，高级电影感，竖屏。

强：

> Vertical editorial-photography scene for an image-led short video. A young office worker sits at a desk with one unfinished task on the laptop. The person remains calm and capable, not lazy or distressed. Around the desk, a highly polished planning system expands into many colored labels, time blocks and priority cards, visually creating too many possible paths before action. Composition begins with the person and single task in the upper-center, with extra environmental detail on both sides for a later pull-back reveal. Keep the lower 30% visually quiet for Chinese-English subtitles. Preserve clear edges between foreground desk objects, subject and background so HyperFrames can add depth motion. Avoid generic head-in-hands procrastination, floating text, illegible UI and decorative neon cyberpunk styling.

### 先生成高风险图片

优先测试：

- 第一帧；
- 长期人物；
- 核心重构；
- 机制图片；
- 结尾回收。

这些决定整体方向。用户认可后再扩展辅助镜头。

### 候选与选择

图片关键且存在多种表达时，可以生成少量结构不同候选。不要无限抽卡。

比较：

- 哪张最能证明内容；
- 哪张构图适合运动；
- 哪张与系列一致；
- 哪张能与下一镜衔接；
- 哪张字幕安全；
- 哪张 AI 痕迹最少。

### 连续性

需要保持人物、物体或空间时：

- 保存锚点图片；
- 明确不可变化的特征；
- 使用第三方 API 支持的参考图片或编辑接口；
- 复用同一构图和光线；
- 必要时从已选图片派生，而不是重新描述；
- 只在内容需要时改变服装、环境或时间。

### 生成图片中的文字

模型生成的中文、英文、数字和界面文字常不可靠。优先生成无字或可控留白图片，再在 HyperFrames 中准确叠加。

### 失败后怎么改

不要只增加“更高级、更电影感”。根据失败类型修改：

- 信息不清 → 重写图片任务；
- 主体位置不对 → 明确构图和安全区；
- 过于抽象 → 加具体行为和物件；
- 风格漂移 → 引用 `DESIGN.md` 中的图片语言；
- 人物不一致 → 使用参考图和固定特征；
- 无法运动 → 增加画幅余量、分层和保护区域；
- 图片漂亮但空 → 增加可见证据或改用另一图片角色。

## 用户素材、截图和证据

不要默认所有图片都需要生成。

### 优先使用用户素材的情况

- 真实人物；
- 产品；
- 品牌空间；
- 原始文件；
- 准确界面；
- 历史资料；
- 用户拥有版权的照片。

### 截图处理

- 裁掉无关 UI；
- 模糊敏感信息；
- 保留来源语境；
- 在 HyperFrames 中放大关键区域；
- 用高亮、框线、遮罩引导；
- 不伪造真实证据。

### 证据与风格

证据图可以保持真实，不必强行统一成生成图风格。通过背景、裁切、边框、光线和转场将其纳入系列视觉系统。

## HyperFrames 实现映射

具体实现遵循 HyperFrames Skill。这里描述导演用途。

| 图片任务 | HyperFrames / GSAP 方法 |
|---|---|
| 拉远揭示环境 | 大图容器 scale 与位置变化，或多层场景 |
| 局部证据聚焦 | 裁切 wrapper、scale、遮罩、对比度、高亮框 |
| 前后对比 | split frame、同构替换、匹配构图、clip reveal |
| 多因素累积 | 多图片层、stagger、SVG 连接线、逐步显现 |
| 具体场景转机制 | 场景物体与图形层共享位置，渐进抽象 |
| 人物与背景分层 | 前景 / 主体 / 背景分别运动，轻量视差 |
| 隐藏原因揭示 | clip-path、mask、拉远、层级显隐 |
| 视觉回收 | 复用资产与构图，改变一个关键关系 |
| 证据标注 | CSS pattern、SVG 框线、精准文字叠加 |
| 语义交接 | matched motion、shared object、方向连续的转场 |

不要为了使用技术而使用技术。若静态构图已经清楚，保持静止也可以。

## 图片审片方法

### 第一遍：只看图，不听旁白

能否大致理解：

- 人物处境；
- 变化；
- 对比；
- 证据；
- 结局。

### 第二遍：听旁白，忽略编辑文字

图片是否增加信息，而不是只是陪伴旁白？

### 第三遍：逐拍暂停

- 第一眼焦点是否明确；
- 信息是否过多；
- 主体是否被字幕遮挡；
- 运动终点是否仍然成立；
- 证据是否可读；
- 是否有 AI 生成错误；
- 镜头交接是否有意义。

### 第四遍：完整播放

- 图片变化和认知变化是否同步；
- 哪一段视觉重复；
- 哪个回报缺少停顿；
- 哪个转场抢内容；
- 结尾回收是否有效。

## 常见失败模式

### 1. 相关配图

每句话都有一张相关图，但没有一张图证明观点。

### 2. 情绪图代替机制

人物一直焦虑、惊讶、发呆，却没有可见原因和变化。

### 3. 一句一图

导致机械切换，图片之间没有关系。

### 4. 所有图片慢推近

运动没有语义，节奏单调。

### 5. 画面复杂等于信息密集

一拍塞入多张图、箭头、标签和装饰，观众不知道先看什么。

### 6. 抽象隐喻泛滥

灯泡、迷宫、棋盘、锁链等常见隐喻替代真实行为。隐喻只有在与内容具体关系清楚时才使用。

### 7. 字幕最后才考虑

最终字幕遮住人物、证据和运动终点。

### 8. 图片风格统一但功能单一

所有图都好看，却只有人物肖像和环境氛围。

### 9. 生成图中的错误文字

把关键证据交给模型生成，导致乱码和错误数字。

### 10. 转场和图片无关

每次随机使用不同特效，没有前后语义关系。
