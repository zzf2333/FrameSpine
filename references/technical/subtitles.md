# 技术附录：中英文双语字幕

> **字幕不是旁白全文的搬运，而是与声音和图片同步推进的阅读节拍。源文标点服务讲述，屏幕字幕默认隐藏句法标点；每个字幕组只在其意义真正到来时出现。**

字幕是基础语言同步功能，不替代图片叙事，也不是本 Skill 的核心创意竞争力。

## 三种文本，三个职责

### Source Script

`SCRIPT.md` 是唯一权威中文旁白源文本。定稿文案的标点、换行、空行、互动句和停顿句都必须保留：它们服务 TTS 停顿、讲述语气、原稿节奏和叙事关系。

### Spoken Text

默认发送给 TTS 的文字来自 `SCRIPT.md`，并同步到派生的 `narration.txt`。它不应为了字幕断句而被改写。

### Display Text

屏幕字幕是从同一段 Source / Spoken Text 导出的阅读文本。它可以：

- 将一句旁白拆成连续出现的短语；
- 默认隐藏句法标点；
- 为同一语义组使用自然英文表达；
- 因阅读和画面推进而换行。

屏幕显示的清理绝不能反向修改 `SCRIPT.md` 或 `narration.txt`。

```text
Source / Spoken Text
刚开始，
三天，一个订单都没有。

Display Text
刚开始

三天一个订单都没有
```

## 推荐流程

```text
SCRIPT.md
→ 火山 TTS
→ HyperFrames transcribe 获取词级时间
→ Agent 按语义组成字幕组
→ 对齐 Storyboard 的图片节拍
→ 清理 Display Text 的句法标点
→ 写自然英文
→ Timed Animatic 人工观看修正
```

转写工具负责给出实际声音的时间参考；Agent 负责语义、叙事和图片推进的断句。不要用逗号、句号、固定字数或脚本自动决定最终字幕组。

使用实际音频转写：

```bash
npx hyperframes transcribe <episode-dir>/assets/audio/narration.wav
```

## 语义字幕组

默认采用**短语级替换**：一个能立刻理解的小意思到来时出现，随旁白和图片推进，到下一组意义到来时替换。不要提前整句常驻，也不要默认逐字高亮。

```text
所有人都在追 AI 的时候

有个失业半年的人

却靠一盒拼豆

赚到了第一笔钱

是不是听起来很离谱

他也觉得离谱
```

字幕本身也是信息释放的一部分。提前显示尚未说出的后半句，会抢在旁白和图片之前泄露事件、答案或回报。

### 怎样判断一个自然短语

同时判断三个信号，优先保护意义完整：

1. **语义单位**：一组只表达一个立即可理解的小意思；
2. **声音停顿**：明显停顿是强断句候选，轻微停顿结合语义判断，几乎无停顿通常保持同组；
3. **视频推进**：新事件、图片揭示或图片关系变化到来时，字幕才切换。

不要为了字数或 TTS 的偶然喘息，在以下位置拆开：

- 修饰语与中心词；
- 否定词与动词；
- 数字与单位；
- 动词与关键宾语；
- 固定词组；
- 转折词与其后核心意思；
- 一个完整的情绪或结果单位。

例如 `三天一个订单都没有` 应保持完整，而不是拆成“一个订单 / 都没有”。

### 与图片节拍对齐

字幕变化应尽量对应视频里正在发生的新动作或揭示：

```text
旁白说到新的事件
→ 图片开始揭示新的内容
→ 新字幕组在该短语第一个词到来时进入
```

“直到有一天”可以独立出现，因为画面正从求职失败切向拼豆盒；“他又拿起了那盒拼豆”应在手真正接触拼豆盒时进入。

允许为了关键图片揭示微调几十到一两百毫秒，但不能造成明显声画错位。最后一个词结束后可短暂停留；下一个事件到来前隐藏上一组。明显停顿时允许短暂无字幕，不要让上一组一直挂到下一件事已经发生。

## 显示标点清理

Source / Spoken Text 保留原始标点。Display Text 默认隐藏用于阅读停顿的句法标点，例如：

```text
，。！？；：、“”‘’……——
```

这不是“删除所有非汉字字符”。保留数字、单位、产品名和技术表达内部有意义的字符：

```text
1.77
9.9
200+
50%
GPT-5
AI 2.0
A/B
didn't
AI-powered
1.77 yuan
```

英文 Display Text 同样可以默认不显示句末标点，但保留英文内部必要字符。清理时优先逐组检查，不要用会伤害专有名词、数字和单位的粗暴全局替换。

## 中文与英文共享同一意义区间

先确定中文语义组，再为这个组写自然英文；中英文使用相同开始和结束时间，但各自按阅读习惯换行。

```text
中文：三天一个订单都没有
英文：Not a single order for three days
```

不要让英文按自己的字数独立切成另一个时间组，除非声音和画面确实发生了第二次推进。英文过长时优先自然压缩表达，不缩小字号或机械逐字翻译。

保持统一：人名、品牌、专有名词、数字、单位、语气和重要概念。

## 推荐尺度

以下是导演倾向，不是自动门禁：

```text
中文：通常 5–12 个汉字；尽量不超过 14 个；有力短语可为 2–4 个字
显示：通常约 0.7–2.3 秒；复杂信息可更久
```

不要为满足长度机械拆坏语义。一个较长但完整的短语可在同一字幕组内分两行；若要拆成两个时间组，必须让拆分同时服务声音、画面和好奇管理。

## 最少字幕记录

字幕数据只服务执行和追溯，不构成审批系统或复杂 Schema。需要记录时，一个轻量文件即可：

```json
{
  "start": 4.28,
  "end": 5.62,
  "source": "三天，一个订单都没有。",
  "zh": "三天一个订单都没有",
  "en": "Not a single order for three days",
  "beat": "B05"
}
```

- `source`：追溯 `SCRIPT.md`，不作为屏幕直接显示文本；
- `zh`：清理显示标点后的中文；
- `en`：同一语义组的自然英文；
- `beat`：与 `STORYBOARD.md` 图片推进对齐。

## 视觉层级与构图

一般建议：

```text
中文字幕：更大、更亮、主要阅读层
英文字幕：更小、更弱、辅助阅读层
```

具体字体、颜色、位置和进入方式来自系列 `DESIGN.md`。双语字幕会占较多垂直空间，因此从图片节拍开始就考虑：

- 字幕安全区；
- 人脸、手、产品和证据保护；
- 图片推拉后是否进入字幕区；
- 平台 UI；
- 最长字幕组的真实高度。

不要等 Final 才把字幕压在图片上。字幕动画应稳定、清楚，不抢图片：轻微进入、必要时少量关键词强调即可；避免每组使用不同效果。

## Timed Animatic 审看

在真实播放中检查：

- 是否按语义而非固定字数断句；
- 是否在词组、数字、否定或关键宾语中间奇怪断开；
- 字幕是否提前泄露尚未到来的旁白；
- 字幕切换是否对应图片事件或揭示；
- 上一组是否停留过久，或短词是否闪得看不清；
- 是否仍显示无意义句法标点；
- 数字、单位、专有名词和技术表达是否被误删；
- 中英文是否属于同一意义单位，并共享时间区间；
- 是否跟随正式声音、可读且不遮挡关键主体。

这些是基础可用性与导演节奏检查，不是创意审批。
